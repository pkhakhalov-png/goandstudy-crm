# Go & Study CRM — обзор для владельца

Краткий бизнес-справочник: что делает система, кто чем пользуется, где что лежит.

**Где живёт:** https://goandstudy-crm.vercel.app
**База данных:** Supabase (PostgreSQL)
**Язык интерфейса:** русский

---

## Что это вообще такое

Своя CRM для образовательной консалтинговой компании. Заменяет связку amoCRM + Google Sheets + мессенджеры. Внутри:

- База клиентов и сделок
- Воронка продаж (канбан) с перепиской в карточке
- Платежи и расходы (план/факт)
- Запись на консультации через публичную ссылку
- Счета через СБП (Т-Банк)
- Аналитика для руководителя отдела продаж
- Портал куратора для работы с активными клиентами

---

## Три роли пользователей

### 1. Администратор (`/admin`)
Полный доступ. Это владелец/бухгалтер.
- Главная с KPI, выручкой, должниками
- Клиенты, платежи, расходы, счета
- Воронка продаж (просмотр + управление)
- Аналитика по менеджерам
- Настройки, кураторы, календарь записей

### 2. Менеджер по продажам (`/sales`)
Видит только своих клиентов и свои сделки.
- Список своих клиентов
- Создание нового клиента
- Своя воронка (только чтение — перемещение делает РОП/админ)
- Свой график приёма консультаций
- Панель срочных задач на главной
- Таблица лидеров отдела (мотивация)

### 3. РОП — руководитель отдела продаж (`/rop`)
Аналитика и управление отделом.
- Планы продаж (по отделу и по каждому)
- Лидерборд, score по менеджерам
- Прогноз выручки (факт + взвешенный пайплайн)
- Скорость ответов клиентам (SLA)
- Зависшие сделки, перекос нагрузки
- Причины потерь, источники сделок
- Конверсии между этапами воронки + AI-детектор проблем
- История действий РОПа (аудит)

### 4. Куратор (`/curator`) — отдельный портал
Работа с клиентами после продажи: ресурсы, шаблоны писем, профиль.

---

## Воронка продаж — главное

Канбан-доска со сделками. Этапы по умолчанию:
`Новые заявки → Контакт → Выявление потребности → Презентация → Возражения → Договор → Первичная продажа → Оплата услуг → Догрев`
Плюс «тупики»: `Не пришёл`, `На будущее`, `Релокация`.

Каждый этап имеет **вес** (0–1) — вероятность дойти до оплаты. Используется для прогноза выручки.

### Карточка сделки содержит:
- Контакт клиента (телефон, email, Telegram, WhatsApp)
- Бюджет и валюту
- Источник (ручной, Telegram-бот, группа в TG, WhatsApp, запись на консультацию)
- **Переписку** с клиентом прямо в карточке (Wazzup24 для TG/WhatsApp)
- Файлы
- Заметки и активность
- Задачи с дедлайном
- AI-подсказку ответа (Claude)

### Откуда приходят сделки
- Ручное создание
- Webhook из Wazzup (WhatsApp + Telegram) — автоматически
- Webhook из Telegram-бота (групповые чаты)
- Публичная форма записи `/book` — создаёт бронь и сделку

## Деньги

### Платежи
Каждому клиенту — график: номер платежа, план-дата, план-сумма, факт-дата, факт-сумма, оплачен/нет. Есть представление `payments_view` со статусом: `paid` / `overdue` / `soon`.

Особенность: при изменении суммы одного платежа система **перераспределяет** остальные неоплаченные так, чтобы сумма по клиенту осталась прежней (если не менять общую).

### Расходы
Делятся по статьям: куратор, менеджер, виза, документы, прочее. Статус: ожидает/оплачено.

### Постоянные расходы
Шаблоны (офис, зарплаты, софт, маркетинг) + записи по месяцам.

### Счета (СБП через Т-Банк)
Создаются из карточки сделки/клиента. Т-Банк присылает колбэк на `/api/tbank-notify` → статус обновляется.

## База данных — основные таблицы

| Таблица | Что хранит |
|---|---|
| `users` | пользователи + роль (admin/salesperson/rop) |
| `curators` | кураторы (для клиентов после продажи) |
| `clients` | клиенты (после конверсии из сделки) |
| `payments` | график платежей |
| `expenses` | расходы по клиентам |
| `fixed_expenses` | шаблоны постоянных расходов |
| `invoices` | счета Т-Банка |
| `schedule_slots`, `bookings` | график консультаций + записи |
| `pipeline_stages` | этапы воронки |
| `deals` | сделки |
| `deal_activities` | история изменений сделки |
| `deal_messages` | переписка с клиентом |
| `deal_files` | файлы в сделке |
| `deal_tasks` | задачи менеджеров |
| `sales_plans` | планы продаж (помесячно) |
| `rop_settings` | настройки РОПа (SLA, веса и т.п.) |
| `rop_actions_log` | аудит действий РОПа |

## Интеграции

| Сервис | Для чего |
|---|---|
| **Supabase** | база + авторизация |
| **Wazzup24** | приём/отправка сообщений WhatsApp и Telegram |
| **Telegram Bot API** | приём сообщений из групповых чатов |
| **Anthropic Claude** | AI-подсказка ответа клиенту |
| **Т-Банк СБП** | выставление счетов и колбэки об оплате |
| **Vercel** | хостинг, автодеплой из ветки `main` |

---

## Что под капотом (коротко)

- **Next.js 16** (App Router) + React 19 + TypeScript
- **Tailwind CSS 4** + свои CSS-переменные (фиолетовый/зелёный/красный акценты)
- Без ORM — прямые запросы к Supabase
- Без UI-библиотек — все компоненты свои

Техническая документация: см. `CRM_FULL_CONTEXT.md` и `AGENTS.md`.

## Что сейчас в работе / планах

Из памяти проекта:
- **Интеграция Wazzup** — инфраструктура готова, подключение аккаунта позже
- **Воронка/канбан вместо amoCRM** — частично сделана, доводится под боевое использование
- **Вся статистика — на главной Дашборда** (не отдельными страницами)
- У РОПа часть кнопок действий в таблицах ещё не проброшена в UI (серверная логика уже есть)

## Кому что показывать

- **Менеджеру** — `/sales` (свои клиенты, своя воронка, график, задачи)
- **РОПу** — `/rop` (аналитика по отделу)
- **Бухгалтеру/владельцу** — `/admin` (всё, включая финансы)
- **Куратору** — `/curator` (свой портал)
- **Клиенту (внешнее)** — только `/book` для записи на консультацию
