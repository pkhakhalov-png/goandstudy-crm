# Раздел 1. Техническое укрепление

## 1.1 Маршрутизация задач

**Было.** Любой воркер брал любую задачу. Публикацию в тему первым забирал
Vercel и ронял с `spawn ssh ENOENT`. Возврат задачи в очередь был основным
механизмом маршрутизации — работа зависела от того, кто успел первым.

**Стало.** У задачи есть исполнитель: `any`, `vercel`, `agent`. Воркер просит
только своё. Возврат остался страховкой.

**Миграция не применена — и это важно.** При её подготовке нашлась ошибка,
которая сломала бы выдачу задач полностью: `create or replace` с третьим
аргументом не заменяет функцию с двумя, а создаёт вторую перегрузку. Аргумент
со значением по умолчанию делает вызов с двумя аргументами подходящим обеим —
Postgres отказывается выбирать. Исправлено: старая функция снимается явно,
всё идёт одной транзакцией, рядом лежит скрипт отката.

**Совместимость:** таблица 276 строк, активных задач 0 — блокировки незаметны.
Добавление колонки со значением по умолчанию не переписывает таблицу.
**Обратимость:** полная. Откат возвращает прежнюю функцию; колонку `runner`
он не удаляет — это единственная необратимая операция, и делать её отдельно.
**Потери данных:** нет.

Пока миграция не применена, код работает по-старому: вставка задачи переживает
отсутствие колонки, вызов функции — отсутствие новой сигнатуры.

## 1.2 Временные и постоянные ошибки

`lib/seo/failure.ts`. Перегрузка, 5xx, обрывы связи — повторить с растущей
паузой. Нехватка денег, неверный ключ, занятый слаг — признать поражение.
Проверено восемью случаями в тесте.

## 1.3 Санитария тела статьи

Проверка качества помечает исполняемую разметку, а перед записью она
вырезается: скрипты, рамки, формы, обработчики событий, ссылки со скриптом,
вставки PHP. Санитария стоит **на всех путях записи**: и в выдаче агенту,
и в прямой публикации по SSH (`publishToTheme`), которую используют шаг
очереди и ручной скрипт.

PHP в теле не исполнялся и раньше — тема читает файл через `file_get_contents`.
Опасность была в JavaScript.

**Существующие материалы проверены без перезаписи:** `scripts/seo-scan-content.ts`
прошёл по всем 77 вышедшим статьям — исполняемой разметки нет ни в одной.

## 1.4 Сверка вышедшей страницы

Добавлены: canonical указывает на себя, адрес есть в `sitemap.xml`, каждая
картинка отдаёт 200, `X-Robots-Tag` и мета-роботс не закрывают, счёт картинок
без `alt`.

Поводом была настоящая ошибка: тег картинки в тексте стоял, файл отдавал 404,
прежняя сверка сказала «всё хорошо».

## 1.5 Каннибализация перестала быть приговором

Четвёртый исход — «спорно»: мало данных (меньше 40 показов или трёх запросов)
или семью держит страница услуги. В CRM у каждой отложенной темы объяснение,
конкурирующие адреса и четыре кнопки: всё равно писать, обновлять ту,
отложить, отклонить.

**География.** «Поступление в вузы Великобритании» и «поступление в вузы
Китая» состоят из одних слов, кроме одного, и склеивались в одну семью. Теперь
страна разводит темы принудительно.

## 1.6 Целостность импорта GSC

Ошибка записи роняет шаг. Каждый прогон оставляет след в
`settings.gsc_import_health`. Пустой ответ при наличии истории помечается
подозрительным — он отличается от настоящего нуля.

**Пропущенные периоды восстановлены, а не только взяты под контроль:**
118 дней подряд, ни одного пустого, ни одного подозрительно тонкого.
Сверка с Google по трём точкам периода — расхождение 0%.

## 1.7 Картинки на сервере

`FAL_KEY` и `IMAGE_PROVIDER` перенесены в production. Проверено боевым
воркером: задача #283 нарисовала обложку и картинку без ноутбука. При сбое
генерации ставится прежняя заглушка — картинка не повод останавливать конвейер.

# Раздел 2. Второй заход

## 2.1 Упавшая задача разобрана

`generate_schema`, пять попыток подряд, ошибка `duplicate key`. Причина: шаг
вставлял предложения разметки, а удалял перед этим только необработанные —
на странице с уже применённой разметкой вставка натыкалась на существующую
строку. Идемпотентность восстановлена: перезапись вместо вставки, применённые
предложения не откатываются. Повторный прогон подтверждает устойчивость.

## 2.2 Внутренние ссылки

Сухой прогон: 55 адресов, 88 ссылок. Таблица с исходным адресом, ответом,
конечным адресом и canonical — `docs/seo/links-audit.tsv`.

Исправлены только однозначные: один переход, ответ 200, страница объявляет
себя канонической. Это 53 адреса. Плюс два шаблона, строивших адреса на лету
(список блога — 77 ссылок, хаб языковых курсов — 32), и ссылки, зашитые в
HTML-строку внутри `functions.php`.

**Не тронуто намеренно:** `/yazykovye-kursy-kitajskogo-yazyka-v-kitae` ведёт
на якорь внутри другой страницы, canonical у цели указывает на родителя. Это
решение о содержании, а не о форме адреса.

**Адреса самих страниц не менялись.** Резервные копии: `/root/backups/theme-links-*.tgz`,
`functions.php.*`, `blog.php.*`, `courses-landing.php.*`.

Результат: на главной, в блоге, на страницах услуг и курсов — ноль ссылок
через переадресацию.

## 2.3 Достоверность существенных утверждений

Семь видов считаются существенными: стоимость, дедлайн, язык, виза, кого
берут, документы, стипендия. Неподтверждённое или просроченное из них **не даёт
нажать «Утвердить»**.

Подтверждение эксперта — не галочка: создаётся заметка, источник и связь с
утверждением, срок продлевается по политике вида. Видно, кто поручился и когда.
Выдуманная ссылка подтверждением не считается — засчитываются только
записанные источники.

Проверено на живой статье #9: восемь существенных утверждений без
подтверждения; после подписи куратора осталось семь.

## 2.4 Источники тем

Добыча из запросов Search Console: если по семье есть спрос, а наша лучшая
страница стоит слабо, это тема. Запас вырос **с 8 дней до 37**: 23 темы без
вопросов и 14 спорных.

У каждой темы записаны источник, намерение читателя, целевая услуга, спрос
в показах и обоснование приоритета.

**Чего нет и почему:** данные Яндекса недоступны — Wordstat требует отдельного
одобрения, Webmaster API отдельного токена. Вопросы клиентов как источник
проверены и оказались пусты: поле сообщения в записях не заполняется, в анкетах
22 ответа «о себе». Изображать сбор, которого нет, не стал.

## 2.5 Обновление существующих статей

Решение «обновлять ту» запускает работу: снимок текущего текста с сайта →
разбор замечаний стандарта и фактов → предложение правок отдельной версией →
разница в `change_sets` → согласование человеком → публикация в режиме
обновления с сохранением адреса → сверка страницы → откат при нужде.

Проверено на живой статье «Что такое нострификация»: снимок версии 1,
предложение версии 2, пять замечаний, 17 102 → 18 225 знаков.

## 2.6 Измерение обращений

**Почему `v_page_deals` был пуст:** таблица `lead_identities` существует, но
её никто не заполнял. Сделки есть — 1038, из них 184 через запись на
консультацию. Формы записи уже собирают адрес, с которого пришли.

**Что сделано:** касание записывается при создании записи на консультацию,
ночной шаг сшивает его со сделкой по `bookings.id`. Сбой статистики не мешает
записи клиента.

**Границы, которые видно на экране:** обращением считается только заявка через
нашу форму. Переход в мессенджер — клик, а не заявка. Звонки, письма и
обращения из телеграм-группы к странице не привязываются. Счёт идёт с
11.09.2026: у прежних заявок источник не размечен и восстановлению не подлежит.

Проверено контрольным обращением: адрес разобран, страница найдена, сшивка
отработала, контрольная запись удалена и в отчёты не попадёт.
