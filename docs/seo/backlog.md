Порядок — по вреду от бездействия, а не по трудоёмкости.

## Срочное

### 1. Применить миграцию маршрутизации
`supabase/migrations/20260911120000_jobs_runner.sql` — вставить в SQL-редактор
Supabase.

Пока не применена, публикацию снова может перехватить не тот исполнитель.
Код переживает отсутствие миграции, но работает по-старому.

**Готово, когда:** `select runner, count(*) from seo.jobs group by 1` возвращает
строки, а в результатах задач воркера Vercel нет шага `article_publish_blog`.

### 2. Достоверность фактов — блокировка публикации
Сейчас реестр знает только числа. Требуется хранить условия: дедлайны,
стоимость, требования к поступающим, язык и сертификаты, документы, покрытие
стипендии, применимость к конкретной программе и набору. Для каждого факта —
источник или подтверждение эксперта, дата проверки, область применимости, срок
актуальности.

Критическое неподтверждённое утверждение должно **запрещать согласование**, а не
висеть предупреждением.

**Готово, когда:** статья с непроверенной ценой или дедлайном не даёт нажать
«Утвердить», и в замечании видно, какого подтверждения не хватает.

### 3. Источники тем, кроме Search Console
Сейчас темы приходят только из GSC — самостоятельных и безопасных осталось
на восемь дней работы.

Добавить: вопросы клиентов из CRM, пробелы тематического покрытия, доступные
источники спроса Яндекса, разбор выдачи через разрешённые интеграции. Для каждой
темы хранить источник, намерение, направление бизнеса, целевую услугу,
сезонность, данные спроса и обоснование приоритета.

Частотность и конкуренцию не выдумывать. Если интеграции нет — сделать понятный
импорт и честно пометить ограничение.

**Готово, когда:** в очереди есть темы минимум из двух источников, и у каждой
видно происхождение.

## Важное

### 4. Полноценное обновление существующих статей
Решение «обновлять ту» сейчас только записывается. Нужен рабочий процесс:
снимок текущего материала и метрик → поиск устаревшего и пробелов → предложение
изменений → просмотр различий в CRM → проверки и согласование → публикация с
сохранением адреса → сверка страницы и возможность отката → измерение результата.

**Готово, когда:** статью можно обновить из CRM, видя построчную разницу, и
откатить одной кнопкой.

### 5. Перелинковка по существу
Проверяется только существование цели. Нужно: релевантность, конечный статус
(не редирект), совпадение с canonical, выявление статей без входящих ссылок,
согласование правок в существующих статьях.

**Готово, когда:** ни одна предложенная ссылка не ведёт на редирект или чужой
canonical, и виден список статей-сирот.

### 6. Согласованная форма внутренних ссылок
165 ссылок ведут на адрес без слэша, который отдаёт 301. Скрипт готов:
`server-agent/fix-trailing-slash.sh` — с копией темы, проверкой синтаксиса и
откатом. **Требует вашего решения:** это массовая правка живого сайта.

**Готово, когда:** `curl -s https://goandstudy.com/blog/ | grep -c 'href="/blog/[a-z0-9-]*"'`
возвращает 0, а выдача и позиции не просели за две недели наблюдения.

### 7. Устойчивость каннибализации по периодам
Пересечение считается за один период. Нужно сравнивать два окна: если
распределение запросов между страницами скачет, это не устойчивая
каннибализация, а шум.

**Готово, когда:** в объяснении решения видно, как делились запросы месяц
назад и сейчас.

## Нужное

### 8. Измерение обращений
`seo.v_page_deals` пуст, переходы не размечены. Нужна разметка посадочной
страницы и связь с заявкой в CRM. До тех пор экран «Эффект» честно показывает
только поисковые показатели.

Клик по мессенджеру заявкой не считать.

**Готово, когда:** для органической посадочной страницы видно число обращений
и явно указано, какая часть переходов не атрибутируется.

### 9. Авторство
Автор — строка в разметке. Пользователь WordPress ничего не решит: статьи не
связаны с записями WordPress. Нужен реальный автор или проверяющий эксперт,
страница с компетенциями, корректное отображение в статье и в разметке.

**Готово, когда:** в статье стоит имя со ссылкой на страницу автора, и то же
имя в JSON-LD.

### 10. Кнопка повтора задачи в CRM
Сейчас упавшую задачу перезапускают запросом к базе.

**Готово, когда:** в очереди у упавшей задачи есть кнопка «Повторить», и она
сбрасывает попытки.

### 11. Откат тела статьи из CRM
Копии на сервере есть, но добраться до них можно только по ssh.

**Готово, когда:** в истории версий статьи есть «Вернуть эту версию на сайт».
