# SEO-конвейер goandstudy: контекст, состояние, что дальше

Обновлено 10.09.2026. Документ самодостаточный — по нему можно вернуться
к работе через месяц, не поднимая переписку.

---

## 1. Что это

Машина, которая сама пишет, проверяет и публикует статьи в блог
goandstudy.com. Человек нажимает кнопку в CRM и читает результат;
всё между этими двумя точками делается без него.

Управление — `crm.goandstudy.com/admin/seo`. Терминал не нужен ни для
одного шага рабочего цикла.

---

## 2. Как устроено

### 2.1 Три части

| Часть | Где живёт | За что отвечает |
|---|---|---|
| CRM | Vercel, Next.js, схема `seo` в Supabase | экраны, кнопки, очередь задач, вся логика |
| Мост | mu-plugin `goandstudy-seo-bridge.php` на WP | чтение и правка страниц WordPress по HMAC-подписи |
| Агент | `server-agent/gs-publish-agent.php`, крон на сервере | то, что требует доступа к файлам темы |

Разделение не случайное. Тема принадлежит `root` и для PHP закрыта на
запись — это защита после взлома. Поэтому публикация статей идёт не через
WordPress, а через агент на сервере, у которого узкий токен и один
разрешённый вид работы. Ключей от базы CRM на сервере WordPress нет.

### 2.2 Статьи блога — не записи WordPress

Ключевой факт, который ломает интуицию. Блог сделан темой: статья это
четыре артефакта, а не пост в базе.

1. тело статьи — HTML-файл в теме;
2. строка в реестре статей (заголовок, описание, категория, дата);
3. обложка 480×320;
4. поднятый флаг пересборки.

Отсюда и агент, и то, что «удалить статью» — это не кнопка в WP-админке.

### 2.3 Очередь

Таблица `seo.jobs` плюс процедуры `claim_jobs` / `complete_job`. Задачи
разложены по дорожкам с ограничением одновременности; зависшая дольше
десяти минут разблокируется сама. Воркеров два:

- `/api/seo/tick` на Vercel — по крону, бюджет 240 секунд из 300;
- агент на сервере WordPress — раз в минуту, забирает только своё.

Шаг, который воркер не умеет, он возвращает в очередь, а не роняет.
Иначе один воркер ломал бы работу другого.

### 2.4 Путь статьи

```
тема из GSC ─> бриф ─> черновик ─> проверка ─> обложка ─> план ссылок
                                      │
                            [экран в CRM: замечания]
                                      │
                       утвердить ─> публикация ─> сверка вышедшей страницы
                                      │
                        индексация ─> проверка индекса (сама, раз в сутки)
```

Каждый переход — шаг очереди. Экран статьи показывает версии, замечания
с цитатами, историю и ссылки.

## 3. Что сделано

### 3.1 Фундамент

- **Инвентарь сайта** — 159 страниц, из них 77 статей блога. Первый обход
  пропустил 61 страницу, дособрано.
- **Search Console** — подключён по OAuth, данные импортируются в очередь.
- **Векторы** — 159/159 страниц векторизованы, отсюда проверка на
  каннибализацию и подбор соседних страниц для перелинковки.
- **Разметка** — JSON-LD раскатан на 129 страниц, кириллица корректная.
  По дороге чинилась порча JSON: WordPress снимал слэши с меты и `Я`
  превращалось в `u042f`.
- **Open Graph** — на всём сайте, с картинкой и запасными источниками
  описания. Раньше ссылки в мессенджерах выглядели пусто.
- **FAQPage** — разметка вопросов на всех 77 статьях, собирается из
  видимого текста, а не дублируется руками.

### 3.2 Качество текста

Два документа задают стандарт: приложение F к ТЗ и разбор 76 живых статей
блога. Где они спорят — выигрывает разбор блога (оглавление, блок «Читайте
также», длина описания). За приложением F остаются язык, факты, обещания и
проверка на каннибализацию.

Проверки в коде, а не в подсказке модели:

- пять разрешённых блоков Gutenberg, никаких классов, стилей и эмодзи;
- 900–1600 слов, 6–14 подзаголовков, обязательный блок «Частые вопросы»;
- призыв в конце — дословный, вставляется кодом. Модель однажды выкинула
  из него слово «бесплатную», после чего текст призыва перестал быть
  предметом её решения;
- ссылки только на существующие страницы;
- **реестр фактов** `seo.claims` — числа в тексте сверяются с реестром,
  неподтверждённое помечается замечанием. Первые десять фактов по Китаю
  внесены со слов куратора.

### 3.3 Публикация

Работает из админки: «Утвердить» → «Опубликовать». Есть сухой прогон,
обновление вышедшей статьи вместо создания дубля, резервная копия реестра
и откат по `php -l`, если правка ломает синтаксис. После публикации
отдельный шаг сверяет вышедшую страницу; если найдено критичное — статья
возвращается в черновик, а не остаётся битой в индексе.

Входящие ссылки расставляются в обе стороны: и в страницы WordPress, и в
файлы темы.

### 3.4 Индексация — то, что доделано сегодня

Две кнопки на экране статьи, и обе честные.

**«Отправить на индексацию»** — IndexNow: Яндекс, Bing, Seznam и Naver
получают уведомление одним запросом. Google так уведомить нельзя: приём
заявок на индексацию у них закрыт с 2023 года, а оставшийся интерфейс
предназначен вакансиям и трансляциям. Google придёт по sitemap сам.

**«Проверить индекс»** — настоящий ответ Search Console через URL
Inspection API, тот же, что показывает «Проверка URL» в их интерфейсе.
Никаких догадок по выдаче. Пример живого ответа:

```
/blog/chto-takoe-gpa-i-kak-ego-rasschitat/   в индексе, обход 09.09.2026
/blog/kak-poluchit-grant-obuchenie-kitae/    URL неизвестен Google
```

Результат пишется в `seo.index_status` и в мету версии, виден на экране
статьи. Плюс шаг `article_index_check` в ночном цикле: пока статья не в
индексе, перепроверка каждые два дня, после попадания — раз в две недели,
и дата попадания проставляется в `articles.indexed_at`. То есть момент
индексации ловится сам, ежедневно нажимать ничего не нужно.

### 3.5 Безопасность

- REST WordPress закрыт целиком, открыт только namespace моста под HMAC.
- Выполнение PHP в `/wp-content/uploads` даёт 403 — проверено пробным
  файлом, файл удалён.
- Тема остаётся за `root`, агент правит её от своего имени с узким токеном.
- Секрет моста ротирован после того, как первое значение попало в вывод.

### 5.2 В коде

- **Каннибализация по семьям запросов.** Сейчас сравниваются документы
  целиком с порогом 0.9 — это ловит только близнецов. Две статьи могут
  бороться за один запрос, оставаясь разными текстами.
- **Подбор тем по семьям запросов.** Сейчас порог 150 показов на один
  запрос; хвост из десяти похожих запросов по 30 показов не виден,
  хотя суммарно это интереснее.
- **Черновики 908 и 909 в WordPress** — переименованы в «[УДАЛИТЬ]»,
  у моста нет удаления. Убрать руками в админке.
- **Sitemap в Search Console** так и не отправлен с августа.
