# Задание: доступы к WordPress для SEO-модуля (этап 5 PRD)

_Для того, кто администрирует сайт goandstudy.com (WordPress). Цель — включить безопасную
публикацию из CRM. Код моста уже написан (`wp-bridge/goandstudy-seo-bridge.php`)._

## Что это разблокирует
- Публикацию сгенерированных статей прямо из `/admin/seo` (по умолчанию — черновик `draft`, публикация отдельным действием после согласования).
- Применение готовых предложений **schema.org** (80 штук уже сгенерированы) на реальные страницы.
- Простановку одобренных внутренних ссылок, meta description, canonical; 301-редиректы; откат версий.

Всё пишущее — идемпотентно и с журналом. Автопубликация не включается, пока не будет 30–50 успешных материалов (PRD §13).

## Что нужно от тебя (чеклист)

| # | Что | Обязательность |
|---|---|---|
| 1 | Установить mu-plugin `goandstudy-seo-bridge.php` в `wp-content/mu-plugins/` | обязательно |
| 2 | Добавить строку с секретом в `wp-config.php` | обязательно |

| 5 | Подтвердить базовый URL сайта (домен блога) | обязательно |

## Пошагово

### 1. Установить mu-plugin
Файл `wp-bridge/goandstudy-seo-bridge.php` из репозитория положить в:
```
wp-content/mu-plugins/goandstudy-seo-bridge.php
```
(если папки `mu-plugins` нет — создать). mu-plugin активируется автоматически, в списке плагинов его не видно — это норма.

Способы залить: SFTP/FTP, файловый менеджер хостинга, или через `wp-cli`.

### 2. Секрет в wp-config.php
В `wp-config.php` (до строки `/* That's all, stop editing! */`) добавить:
```php
define('GS_SEO_BRIDGE_SECRET', '4a25d92d2db32fd3fb8346221c48e8f7f52f17a293b55148b6f87ab9f78ae01a');
```
Этот же секрет я впишу в env CRM как `WP_BRIDGE_SECRET` — по нему проверяется HMAC-подпись каждого запроса (окно 5 минут). Можешь сгенерировать свой (`openssl rand -hex 32`) — тогда пришли какой, но **не в открытый чат**, а впишем в env напрямую (как делали с GSC).

### 3. Проверить доступность REST
Открой в браузере:
```
https://<домен-блога>/wp-json/goandstudy-seo/v1/lookup?key=test
```
Ожидается ответ вида `{"code":"gs_auth", ...}` (401 — «нет подписи»). Это **хорошо**: значит маршрут живёт и требует подпись.
- Если видишь 404 — mu-plugin не подхватился (проверь путь/права).
- Если видишь страницу логина / basic-auth окно / блок от security-плагина (Wordfence, iThemes) — нужно **разрешить доступ к `/wp-json/goandstudy-seo/`** снаружи. Это частая причина, по которой раньше REST был закрыт.

### 4. (Желательно) Application Password
Нужен только для загрузки изображений и стандартного REST. Создать:
- WP-admin → Users → выбрать пользователя роли **Editor** (не Administrator) → раздел **Application Passwords** → имя «goandstudy-seo» → **Add**.
- Полученные логин и пароль (вид `xxxx xxxx xxxx xxxx`) — впишем в env как `WP_USER` / `WP_APP_PASSWORD`.

### 5. Базовый URL
Подтверди точный адрес WordPress (например `https://goandstudy.com` или `https://blog.goandstudy.com`). Это важно и для атрибуции (этап 7): в идеале блог на том же registrable-домене, что Tilda и `/book`.

## Как проверю, что всё работает
После установки я прогоню через мост безопасный `lookup` и создание тестового **черновика** (не публикация), затем `rendered` — проверю, что тема сайта не ломает canonical/schema. Если ок — подключу применение schema к 80 страницам и публикацию статей по согласованию.

## Безопасность (уже заложено в мост)
- Аутентификация — HMAC-подпись тела запроса + временное окно 5 минут (никаких паролей в трафике).
- Права минимальные; App Password — на роль Editor, не Administrator.
- Все записи идемпотентны (по мете `_gs_seo_key`, не по slug) — дублей постов не будет.
- Первая версия всегда `draft`; публикация — отдельное согласованное действие.
- Журнал операций в таблице `wp_gs_seo_log` для сверки.

### Минимум, чтобы стартовать
Пункты **1, 2, 3, 5** (mu-plugin + секрет + открыть REST + URL). Application Password (4) можно добавить позже — без него не будет только загрузки картинок.
