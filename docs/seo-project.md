_Обновлено: 2026-09-09 · Домен: goandstudy.com · Единый источник по проекту._

---

## 1. Что это

Встроенный в CRM SEO-движок: сам обходит сайт, тянет Google Search Console, раскладывает
страницы по темам, находит проблемы и точки роста, приоритизирует их в план работ, помогает
планировать статьи без каннибализации и фиксирует эксперименты. Цель — не «генерировать тексты»,
а автоматизировать **правильное SEO-решение** и весь жизненный цикл страницы: от возможности до
публикации, индексации и выручки.

Интерфейс: **`/admin/seo`**. Язык — русский. Изолированная схема БД `seo` (основную CRM не трогает).

## 3. Что работает (8 вкладок `/admin/seo`)

| Вкладка | Содержимое |
|---|---|
| **Обзор** | трафик 28 дн с трендом, средний CTR, ближайшие приоритеты, находки по видам, счётчики |
| **Возможности** | единый план: решение (UPDATE/EXPAND/MERGE/SCHEMA/FIX/CREATE/REVIEW), риск, прогноз, приоритет; пересчёт, фильтры, отклонить, «▶ эксп.» |
| **Страницы** | инвентарь + клики/показы/позиция из GSC, кластер, число находок |
| **Кластеры** | 10 тем (spherical k-means), распределение, разбивка service/article |
| **Статьи** | создание темы с авто-привязкой к кластеру, анти-дубль, подсказки перелинковки; 19 кандидатов из content_gap |
| **Эксперименты** | baseline из GSC (28/56/90 дн), одна переменная, outcome/rollback |
| **Schema** | 82 готовых JSON-LD (только проверяемые поля), разворачиваемый предпросмотр |
| **Находки** | сырые сигналы 12 видов с привязкой к кластерам |

Модуль **самообновляется** раз в сутки (тик воркера ставит цепочку пересчёта; pg_cron обрабатывает).

## 4. Архитектура (кратко)

```
GSC + сайт (краул) + эмбеддинги
        ↓
инвентарь → кластеры → находки (инвентарные + технические + GSC)
        ↓
Opportunity Engine (решение + приоритет + прогноз)
        ↓  [человек]
Эксперименты (baseline) · Статьи (темы) · Schema
        ↓  [этап 5, ждёт WP]
WordPress Bridge → публикация → индексация → выручка
```

- **Стек:** Next.js 16, React 19, TypeScript; Supabase Postgres (схема `seo`), pgvector; Vercel serverless (`maxDuration 300`).
- **Очередь:** таблица `jobs`, выдача `claim_jobs()` (FOR UPDATE SKIP LOCKED), фоновый воркер `/api/seo/tick`, pg_cron раз в минуту.
- **Эмбеддинги:** Voyage `voyage-3` (1024).
- **Ключевые таблицы:** `pages`, `link_edges`, `gsc_daily`/`gsc_page_daily`, `findings`, `opportunities`, `experiments`, `topics`, `page_schema`, `settings`.

## 5. Что показали данные (ключевые инсайты)

1. **Своя CTR-модель опровергла внешние нормы.** Позиция 1 на сайте даёт ~7,7% CTR, а не «28%». Все CTR-возможности пересчитаны по данным сайта, не по внешним кривым.
2. **CTR-провал — самый быстрый рост.** Страницы в топ-10 по тысячам показов почти не кликают: «phd» 11 643 показа / CTR 0,2%, «toefl цена» поз.5 / ~0%. Лечится заголовком и сниппетом, контент не трогая. (Отдельно: опечатка в URL `/blog/chto-takoe-pdh` → `phd`.)
3. **Каннибализация оказалась мифом на 17/17.** По правилу §5.5 (чередование лидера + нестабильность позиции) подтверждённых 0; 16 — кандидаты на ручную проверку интента. Совпадение запроса ≠ каннибализация.
4. **Технически сайт чист** по критическим проверкам (canonical/robots/noindex/HTTP = 0 проблем).
5. **82 страницы без schema** — в основном Tilda-страницы услуг; JSON-LD сгенерирован, ждёт применения через WP.

## 6. Данные и доступы

**Подключено:** Google Search Console (OAuth, импорт 152k строк запросов), Voyage-эмбеддинги, Supabase.

**Не хватает (гейты этапов):**
| Нужно | Разблокирует |
|---|---|
| WordPress: mu-plugin(v0.2)+секрет+открыть namespace | публикация + применение schema (этап 5) |
| SERP-провайдер (DataForSEO/SerpApi) | внешний спрос, новые темы (этап 2 полн.) |
| Эксперт-ревьюер + ретро-наполнение | бриф/факты/генерация (этапы 3–4) |
| — | атрибуция (этап 7): Tilda **не используется**, всё на goandstudy.com — упрощено |

WordPress: сайт был скомпрометирован через REST (июль–авг), поэтому REST закрыт намеренно. План
открытия — только namespace `goandstudy-seo/` под HMAC (см. `docs/wordpress-server-changes.md`).

## 7. Дорожная карта (этапы PRD v2.0)

| Этап | Статус |
|---|---|
| **0. Валидация находок** | ✅ **готово** — своя CTR-модель, агрегация по URL, прогноз, каннибализация §5.5, критич. техпроверки, приоритет schema |
| **1. Эксперименты** | ✅ ядро готово (таблица + baseline из GSC + «▶ эксп.»); спринт с тестами — по готовности |
| **2. Decision Engine / возможности** | ✅ ядро готово (таблица `opportunities`, эвристика решений, приоритет, прогноз); внешний спрос — ждёт SERP-провайдера |
| **3. Бриф / источники / факты** | ⏳ ждёт эксперт-ревьюера |
| **4. Генерация и QA** | ⏳ после этапа 3 |
| **5. WordPress Bridge** | ⏳ код готов (v0.2), ждёт открытия сервера |
| **6. Индексация / мониторинг** | ⏳ после публикации |
| **7. Атрибуция / выручка** | ⏳ упрощён (нет Tilda); ждёт трекер + этап 5 |

Дополнительно сделано вне этапов: тематическая кластеризация, генерация schema, кандидаты статей
из content_gap, дашборд, самообновление данных.

## 8. Как оперировать

**Из интерфейса:** кнопки на вкладках — «Запустить инвентарь», «GSC-находки», «Технический аудит»,
«Пересчитать находки/кластеры/очередь», «Сгенерировать schema», «Создать статью», «▶ эксп.».

**Локальные скрипты против прод-БД** (`npx tsx scripts/<файл>`):
`seo-run-inventory` · `seo-recrawl` · `seo-embed` · `seo-cluster` · `seo-gsc` · `seo-gsc-findings` ·
`seo-technical` · `seo-opportunities` · `seo-schema` · `seo-gap-topics` · `seo-wp-test` (после открытия WP).

**Ближайший практический шаг (без доступов):** `/admin/seo/opportunities` → верхние UPDATE — готовые
CTR-эксперименты («phd» +22, «toefl» +14 кл/28д). Жмёшь «▶ эксп.» — фиксируется baseline, потом
правишь title/description, через 28 дней сверяем.
