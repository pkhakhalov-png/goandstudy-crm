# План внедрения PRD v2.0 — SEO Content Engine

_Составлено: 2026-09-09 · на основе `goandstudy-seo-prd-v2_0.md` + фактического состояния кода/прод-БД_

Это не пересказ PRD, а привязка его к тому, что уже построено: **что есть → что достроить → в каком порядке → что от тебя нужно**.

---

## A. Где мы сейчас относительно PRD

PRD оценивает готовность так: аналитический фундамент 65–70%, полный конвейер 45–50%.
Разложим по нашим фактическим модулям.

| Возможность PRD | У нас сейчас | Готовность | Что не так |
|---|---|---:|---|
| Инвентарь + граф ссылок | ✅ `pages`, `link_edges`, краул, JSON-LD | 8/10 | ок |
| GSC | ✅ импорт `date×page`, `date×page×query` | 5/10 | **нет сегментов** device/country/appearance, нет сравнения периодов/YoY |
| Эмбеддинги | ✅ Voyage 159/159 | 9/10 | ок |
| Кластеры | ✅ spherical k-means, центроиды | 7/10 | не заменяют интент |
| Находки | ✅ 11 типов, 555, привязка к кластерам | 6/10 | CTR по **внешней норме** (нельзя), задачи **по строкам запросов**, не по URL; каннибализация без проверки чередования позиций/интента |
| Выбор новых тем | ⚠️ `topics` с кластером, анти-дубль | 4/10 | нет внешнего спроса (SERP-провайдер, Trends, вопросы из CRM) |
| Генерация статьи | ❌ нет | 2/10 | нет брифа, источников, фактов, QA |
| Автопубликация (WP) | ⚠️ код Bridge есть, инертен | 1/10 | не подключён к сайту |
| Индексация/мониторинг | ❌ нет | 2/10 | нет машины состояний, когорт |
| Атрибуция/выручка | ❌ нет | 1/10 | нет трекера, сшивки с `deals` |

**Вывод:** мы закрыли «что происходит с сайтом». PRD достраивает «что делать следующим, чтобы получить клиентов». Ключевое: **этап 0 (валидация находок) переделывает то, что мы уже сделали** — иначе Decision Engine строится на ложных приоритетах.

## B. План по этапам (нумерация PRD)

Для каждого — что уже есть у нас, конкретные задачи в нашем коде, миграции.

### Этап 0 — Валидация находок (недели 1–4) · НЕ сдвигается
Цель G1: находки не создают ложных приоритетов. **Это в основном доработка нашего `lib/seo/findings.ts` и GSC-импорта.**

- **0.1 Сегментация GSC.** Расширить `scripts/seo-gsc.ts` / `gsc_import`: тянуть измерения `device`, `country`, `searchAppearance` (сейчас только `date/page/query`). Новые таблицы/колонки (миграция `010`): `gsc_page_daily` + сегменты, `settings.brand_terms`. Сравнение период-к-периоду и YoY (у нас глубина до 16 мес — можно тянуть YoY).
- **0.2 Собственная CTR-модель.** Заменить хардкод `expectedCtr()` в `findings.ts` на медиану CTR **сайта** по `(позиция-бакет × device × country × brand)` за 90 дней при n≥30, откат на широкий срез. Функция `expected_ctr` (миграция `017` или расчёт в TS).
- **0.3 Группировка по URL.** Переписать `computeGscFindings`: striking/CTR/каннибализацию агрегировать **до URL** перед выдачей (сейчас — по строкам запросов). 6 строк из 3 страниц → 3 задачи.
- **0.4 Каннибализация по 5.5.** Добавить проверку чередования лидера по дням (≥40%/≥40%), нестабильности позиции, интента — не только пересечение запроса. Перепроверить наши **18** случаев.
- **0.5 Технический приоритет.** Явная проверка `canonical/robots/noindex/HTTP` как критическая (у нас есть поля, нужен отдельный вид находки с высшим приоритетом). Пересчёт приоритета schema по формуле 5.6 (не «82 работы»). Понизить `llms_txt_missing` до эксперимента.
- **0.6 Формулировки в UI.** Убрать «средний CTR 1,3% = низкий» и «норма 3–5%» из отчётов; sitemap «помогает обнаружению, не гарантирует индексацию».
- **0.7 Битые ссылки.** Устранить 3 `broken_link` (это реальный тех-долг).

**Результат:** наши 555 находок пересчитаны по честным правилам.

### Этап 1 — Контролируемый спринт (недели 5–8) · не сдвигается частично
Цель G3: подтвердить логику на реальных данных. Таблица `experiments` (миграция `014`) + раздел UI «Эксперименты».
- 3 CTR-теста (переписать title/description страниц из отчёта §5.1: `phd`, `gpa`, `toefl`), 5 striking-distance, 3 каннибализации, 10 страниц schema.
- Baseline (28/56/90 дней) + контрольная группа 5 страниц. Наблюдение 28–56 дней.
- Миграция URL `pdh → phd` строго по регламенту 5.8 (создать новый → 301 → обновить ссылки → self-canonical → sitemap).
- **Gate:** ≥60% гипотез подтверждены/опровергнуты, ни одного `degraded` без причины — иначе правила пересматриваем.

### Этап 2 — Decision Engine (недели 9–13)
Цель G2. Миграция `011` (`opportunities`, `priority_weights`).
- Сущность `opportunities`: единая очередь вместо 555 находок; `decision` (CREATE/UPDATE/EXPAND/MERGE/REPOSITION/REDIRECT/LINK_ONLY/IGNORE) + `decision_reason` + risk + confidence.
- Классификация интента (информационный/коммерческий/навигационный), business score по формуле 7.3 (веса в `settings`).
- Подключить внешний спрос: **SERP Data Provider** (DataForSEO/SerpApi) + Google Trends + **вопросы клиентов из CRM** (наше преимущество). Ночной пересчёт.
- UI: вкладка «Возможности»; «Находки» становится техническим источником.

### Этап 3 — Бриф, источники, факты (недели 14–19)
Цель G4. Миграции `012` (`briefs`), `013` (`sources`, `source_snapshots`, `claims`, `claim_policy`, `claim_sources`, `expert_notes`).
- `Content Brief` (24 поля) с обязательным `unique_value` (ответ на «что здесь есть, чего нет в типовой статье») — блокирующее правило против scaled content abuse.
- Реестр фактов: safe-fetch источников, снапшоты в Supabase Storage, извлечение claims, `claim_policy` (приложение D), квалификаторы.
- **Экспертный слой** (`expert_notes`) — узкое место: владелец-консультант, форма в панели, ретро-наполнение 20–30 записей.
- Калибровка QA-проверки фактов на 10 статьях (FP≤15%, FN≤5%), до порогов — режим `warning` + 100% вычитка.

### Этап 4 — Генерация и QA (недели 20–24)
Цель G4. Пайплайн из §11 (19 шагов, lane `production`, fan-in). Три группы QA (факты/редактура/SEO). Первые 5 материалов, 100% вычитка. Anti-дубль (у нас уже есть база — `createTopicWithCluster`).

### Этап 5 — WordPress Bridge (недели 25–28) 🔒 нужен доступ
Цель G5. У нас **код Bridge уже написан** (`wp-bridge/goandstudy-seo-bridge.php`, `lib/seo/wp.ts`) — надо: доустановить mu-plugin на сайт, добавить операции из приложения B (rollback, media, redirects, rendered), идемпотентность по мете, первая версия всегда `draft`.

### Этап 6 — Индексация и мониторинг (недели 29–32)
Цель G6. Миграция `014` (`article_states`). Машина состояний (18 + 10 ошибочных), `post_publish_verify`, когорты 7/14/28/56/90, URL Inspection API (~2000/сут). UI «Мониторинг».

### Этап 7 — Атрибуция и самообучение (недели 33–38) 🔒 нужен доступ
Цель G7/G8. Миграция `016` (`attribution_events`, `lead_identities`, `v_page_revenue`). Трекер `track.js`, `/api/track` + `/api/track/lead`, webhook Tilda, кука с сервера, consent. Сшивка `anon_id` → `deals` → договор → выручка. Калибровка business score по факту.
> **Можно и нужно начать раньше** (недели 6–7): поставить трекер и webhook — данные копятся, к этапу 7 будет полугодовая история.
