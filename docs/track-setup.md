# Счётчик переходов: установка на сайт

_17 сентября 2026. Файл: `wp-bridge/goandstudy-track.php`._

## Зачем

CRM видит заявку — она приходит через форму. Переход не видит никак: человек
открыл статью, почитал и ушёл, и в базе от этого не остаётся ничего.

Без счётчика на вопрос «окупается ли блог» ответить нельзя: видно только тех,
кто дошёл до формы, и не видно, сколько людей вообще читало.

Приёмная сторона уже готова и проверена: `/api/track` в CRM принимает события,
привязывает их к странице и вырезает из источника перехода всё лишнее.

## Куда ставить

```
/var/www/html/wordpress/wp-content/mu-plugins/goandstudy-track.php
```

Рядом уже лежат `goandstudy-seo-bridge.php` и `gs-security.php` — то же место.

**Почему mu-plugin, а не правка темы.** Агент публикации пересеивает тему при
каждой новой статье: меняет сид-флаг в `functions.php` и заставляет WordPress
перечитать файлы. Фрагмент внутри темы рано или поздно уехал бы вместе с
пересевом, причём молча. Mu-plugin переживает и пересев, и смену темы.

## Пошагово

**1. Скопировать файл**

```bash
scp wp-bridge/goandstudy-track.php \
  root@72.56.242.202:/var/www/html/wordpress/wp-content/mu-plugins/
```

**2. Проверить синтаксис на сервере**

```bash
ssh root@72.56.242.202 "php -l /var/www/html/wordpress/wp-content/mu-plugins/goandstudy-track.php"
```

Ожидается `No syntax errors detected`. Если ошибка — файл не дописался, копируй
заново и не оставляй его на месте: mu-plugin с ошибкой роняет весь сайт.

**3. Права как у соседей**

```bash
ssh root@72.56.242.202 "chown root:www-data /var/www/html/wordpress/wp-content/mu-plugins/goandstudy-track.php && chmod 644 $_"
```

**4. Проверить, что фрагмент появился на странице**

```bash
curl -s https://goandstudy.com/blog/postuplenie-v-ssha/ | grep -c "gs_sid"
```

Ожидается `1`. Если `0` — mu-plugin не подхватился: проверь путь и права.

**5. Открыть статью в браузере и посмотреть, доехало ли**

Открой любую статью блога **в режиме инкогнито** — залогиненных сотрудников
счётчик намеренно не считает. Потом скажи мне, я проверю запись в базе.

## Что собирается и что нет

| Собирается | Не собирается |
|---|---|
| адрес открытой страницы | имя, телефон, почта |
| откуда пришли — только домен и путь | поисковый запрос из адреса источника |
| метки кампании: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` | отпечаток браузера, экран, шрифты |
| случайный номер сессии на время вкладки | адрес IP в явном виде |

Анонимный идентификатор ставит сама CRM своей кукой на `.goandstudy.com`, живёт
год. Нужен ровно для одного: связать несколько просмотров одного человека в одну
цепочку касаний, чтобы потом привязать к ней заявку.

Заголовок «не отслеживать» уважается: если браузер его прислал, счётчик молчит.

## Кого счётчик не считает намеренно

- **Залогиненных.** Свои заходят на статьи чаще читателей, и без этой отсечки
  отчёт показал бы не интерес аудитории, а нашу собственную работу.
- Админку, предпросмотр, ленты RSS и запросы роботов.

## Если что-то пойдёт не так

Счётчик написан так, чтобы не мешать сайту: любая его ошибка гасится, страница
рендерится как обычно. Но если нужно снять быстро — просто удали файл:

```bash
ssh root@72.56.242.202 "rm /var/www/html/wordpress/wp-content/mu-plugins/goandstudy-track.php"
```

Ничего, кроме счётчика, при этом не сломается.

## Чего этот фрагмент пока не делает

Не считает переходы из Telegram и VK — постов ещё нет. Но метки `utm_campaign`
и `utm_content` он уже передаёт, и когда посты появятся, переход с поста
свяжется с пакетом и публикацией без правок на стороне сайта.
