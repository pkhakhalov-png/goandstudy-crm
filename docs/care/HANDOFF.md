## 1. Что это

Новый кабинет куратора, который собирается **рядом** с действующей CRM и
включается по одному клиенту. Действующие `/curator/*` и `/client/*` не
меняются вовсе.

Помощник читает дела и отвечает на вопросы куратора. Дальше по плану он
начнёт готовить напоминания и разбирать встречи в факты — но **предлагать**,
а не делать: выполнение всегда отдельный шаг после решения человека.

**Документы:**

| Файл | О чём |
|---|---|
| `docs/care/PLAN_CURATOR_V2_BUILD.md` | План сборки: правила, этапы, что нужно от владельца |
| `docs/DESIGN_CURATOR_V2.md` | Дизайн: каркас, экраны, токены, язык интерфейса |
| `docs/ARCH_CURATOR_V2.md` | Архитектура: изоляция, слои, флаги, перенос |
| `docs/care/MIGRATIONS.md` | Реестр миграций: что применено, когда, контрольные суммы |
| `docs/care/CHANNELS_REALITY.md` | Диагностика каналов связи (важно для пилота) |
| `docs/care/BOT_ROLLOUT.md` | Инструкция кураторам: как добавить бота в группу |
| `docs/care/OWNER_SETUP.md` | Инструкция владельцу: бот, Vercel, переменные |
| `AUDIT_STATE.md` | Аудит действующей системы (с поправкой про RLS) |

## 5. Грабли, на которые уже наступили

Каждая стоила времени. Не наступайте второй раз.

**Тест прав должен считать строки, а не код ответа.** RLS отказывает не
ошибкой, а пустотой: нет политики — 200 и `[]`. `selftest-perms` показывал
«чтение клиентов прошло», пока роль не видела ни одной из 75 записей.
Исправлено миграцией 007 и признаком `ждёмСтроки` в проверке.

**RLS в боевой базе включён, хотя миграции говорят обратное.** Его включали
позже через панель. `AUDIT_STATE.md` поправлен.

**Превью Vercel закрыто Deployment Protection.** Телеграм SSO не проходит.
Обход — `x-vercel-protection-bypass` параметром адреса. **Без
`x-vercel-set-bypass-cookie`**: с ним Vercel отвечает 307, а Телеграм
редиректы не ходит.

**У секрета вебхука Телеграма ограниченный алфавит** — `A-Z a-z 0-9 _ -`.
`openssl rand -base64` даёт `+`, `/`, `=`, и `setWebhook` отвергает с
невнятным `Bad Request: bad webhook`. Нужен `-hex`.

**Групп в Телеграме 698, а не 2.** Двойка была количеством заполненных
привязок: автопривязка ищет в названии группы телефон, которого там не
бывает. Подробности — `docs/care/CHANNELS_REALITY.md`.

**`deal_messages` роли не выдана и не должна быть.** Там вся воронка продаж.
Для названий групп сделано узкое представление `care.group_chats` (миграция
009): чат, название, период, количество. **Ни строчки текста.**

**Текст переписки контуру недоступен.** Видно, что она есть, сколько и за
какой период. Открыть содержимое — отдельное решение владельца; понадобится
на этапе 4.

**Помощник по умолчанию отвечает в Markdown.** Панель показывает текст как
есть — звёздочки останутся звёздочками. В системной части это запрещено явно.

**Инструменты обязаны называть клиента именем.** Первая версия печатала
`b5d1f7f9 — запрос требований к портфолио`: строка верная, прочитать нельзя.

**На `claude-opus-5` нет `temperature` и `budget_tokens`** — оба дают 400.
Глубина задаётся `output_config.effort`. Размышление включено по умолчанию.

**Компоненты React называть латиницей.** Правило `react-hooks/rules-of-hooks`
опознаёт хук по префиксу `use`, компонент — по заглавной латинской букве.
Кириллические имена оно отвергает. Тексты и комментарии — русские.

**`tsconfig.json` включает `**/*.ts`** — тесты попадают под проверку типов при
сборке. Править `tsconfig.json` нельзя (нет в списке исключений плана).

## 6. Правила контура (раздел 0 плана)

Нарушение — стоп и вопрос владельцу, а не обход.

1. Новый код только в `app/care/**`, `app/api/care/**`, `lib/care/**`,
   `supabase/migrations/care/**`, `scripts/care/**`, `tests/care/**`,
   `docs/care/**`.
2. Файлы вне этих каталогов не редактируются. Исключения, каждое отдельным
   коммитом с префиксом `shared:` — их уже три и больше не нужно:
   `middleware.ts`, `eslint.config.mjs`, `package.json`.
3. Из контура нельзя импортировать `lib/supabase/server.ts`, `lib/ai.ts`,
   пишущие модули старой CRM. Ловит линтер.
4. `createAdminClient()` в контуре не используется никогда.
5. Контур пишет только в схему `care`. В `public` — ни одного `INSERT`.
6. Каждая миграция с парным откатом, через `apply.ts`, запись в
   `MIGRATIONS.md`.
7. Персональные документы клиентов в модель не отправляются до решения
   владельца по провайдеру и DPA.
8. Любая отправка наружу — только через `care.outbound_actions` и только при
   `external_sends = true` И включённом флаге `outbound` у клиента.
9. Модель не выполняет действие сама — создаёт предложение.
10. Флаги по умолчанию выключены.

## 7. Этап 3 — что построено и чего не хватает

**Построен весь путь.** Не работает только последний шаг — и это правильное
состояние, а не недоделка.

```
задача «ждём клиента» со сроком
        ↓  правило reminder_document_due (lib/care/jobs/reminders.ts)
предложение care.proposals(kind='reminder')
        ↓  экран /care/review/reminders — очередь «1 из N»
решение куратора: отправить · пропустить (с причиной) · я написал сам
        ↓  ворота lib/care/gate/outbound.ts — пять проверок
care.outbound_actions(queued)  ИЛИ  (cancelled + причина)
        ↓  задание send_outbound в тике
sendMessage care-ботом
```

**Пять проверок ворот**, порядок не случаен:

1. `care.env_marker.external_sends` — рубильник. **Сейчас выключен.**
2. флаг `outbound` для этого клиента
3. свежесть данных: хэш состояния дела совпадает с тем, что было при
   подготовке. Не совпал — предложение гаснет
4. тихие часы (по умолчанию 21:00–09:00 Europe/Moscow)
5. получатель из `care.contacts` дела, **не из payload**

**Подстановка в шаблон механическая, не моделью.** План допускал модель;
подставить три значения — работа, где модель может только ошибиться. Проверка
регулярками осталась вторым рубежом: не остался ли плейсхолдер, есть ли дата,
есть ли имя.

**Оборвавшаяся отправка → `status='unknown'`, без повтора.** Bot API не
принимает вопрос «отправлял ли я вот это». Повторить — можно прислать второе
сообщение; считать отправленным — можно не прислать вовсе. Честное «не знаю»
дешевле обеих ошибок: человек проверит чат за десять секунд.

**Шаблоны утверждены владельцем 30.09.2026** («потом поправим если что»).
Лежат в `care.settings.templates`, меняются строкой в базе без выката кода.

**Чего не хватает от владельца:**

| Что | Где меняется |
|---|---|
| Тихие часы и часовой пояс | `care.settings.quiet_hours`, `timezone` |
| Разрешить отправки | `care.env_marker.external_sends = true` — **только миграцией** |
| Включить флаг `outbound` клиенту | `setup-team.ts --флаг outbound --кому <id>` |
| Перевести дело на v2 | `care.cases.automation_owner = 'v2'` — иначе правило его не видит |

**Два теста помечены `skip`** — они проверяют третью и пятую проверки ворот, а
до них при выключенном рубильнике не доходит. Включатся вместе с отправками.
Флаг в тестах намеренно не переключается: тест, который включает отправки и
выключает обратно, при падении посередине оставляет боевой контур с открытой
дверью.
