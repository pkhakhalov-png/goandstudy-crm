# Каналы связи: что есть на самом деле

**Дата:** 28.09.2026. **Окно:** 90 дней. **База:** боевая, `pxtwaxhmygnssyyowrgr`.
**Метод:** только чтение, `scripts/care/channels-report.ts` (повторяется в любой момент).

Повод для проверки: в `STATUS.md` стояло «группа в Телеграме есть у 2 клиентов
из 75». Владелец возразил, что переписка ведётся в группах и бота можно
добавить во все, то есть дело не в отсутствии групп, а в незаполненной
привязке. **Возражение подтвердилось полностью.**

---

## Главный вывод

Групп **698**, а не 2. Из них живых за 90 дней — **508**.

Двойка — это не количество групп, а количество заполненных привязок
`clients.tg_group_chat_id`. Привязка ставится автоматически и единственным
способом: старый вебхук ищет в названии группы **телефон** и сверяет его с
`clients.phone_normalized`.

**Телефона нет ни в одном из 472 названий.** Названия выглядят так:

```
Релокац х Вячеслав / Сербия учеба 18.03.2026
Анастасия Чикина ( поступление на магистратуру )
Циглинцев Дмитрий Словакия ПС
Хуснутдинова Сафина Китай Языковые курсы
```

Имя есть, страна есть, дата есть — телефона нет. Механизм привязки искал то,
чего в данных не бывает, и поэтому не сработал ни разу за полгода. Две
существующие привязки проставлены как-то иначе.

## Ответ на вопрос: сколько групп реально есть

Из **73** клиентов без `tg_chat_id`:

- **25 групп существуют и старый бот их видит.** Привязка проставляется
  одним `UPDATE` по данным, которые уже лежат в базе. Руками заводить
  ничего не нужно, care-бота добавить нужно.
- **Из них 15 — активные клиенты.** Это и есть реальная основа пилота.
- **6 клиентов не сопоставить** — в карточке нет фамилии, только имя.
  Чинится в CRM или разбирается куратором глазами.
- **Остальные ~42** — группы по имени не нашлись. Часть наверняка есть под
  другим названием (фамилия без имени, прозвище, только страна), часть
  относится к завершённым клиентам, где группа могла быть удалена.

Из 698 групп к клиентам сопоставляются 26. Остальные ~670 — это сделки
воронки продаж: заявки, которые не стали клиентами, релокационные группы и
прочее. Их к кабинету куратора привязывать не нужно.

## Как отличить группу от личного чата

Можно, и в нескольких местах сразу.

В `app/api/telegram/webhook/route.ts:94`:

```ts
const isGroup = msg.chat.type === 'group' || msg.chat.type === 'supergroup'
```

Что сохраняется:

| Где | Поле | Значение |
|---|---|---|
| `deal_messages.metadata` | `chatType` | `group` · `supergroup` · `private` |
| `deal_messages.metadata` | `tgChatId`, `chatTitle` | идентификатор и название |
| `deals.custom_fields` | `is_group`, `tg_chat_type`, `tg_chat_title` | то же, на уровне сделки |
| `deals.source` | — | `telegram_group_bot` для групп (481 сделка) |
| `clients.tg_group_chat_id` | — | заполняется только при совпадении телефона |

**Осторожно с ключом.** В `deal_messages.metadata` признака `isGroup` нет —
есть `chatType`. Первая версия диагностики искала `isGroup` и показывала
«групп: 0» при 698 существующих. В скрипте это теперь закомментировано прямо.

## На каком канале возможен пилот

**Только Telegram, только группы.** Других работающих каналов нет: Wazzup не
записал ни одного сообщения, личных чатов не существует.

Что это значит практически:

1. **Care-бота надо добавлять в группы вручную.** Bot API не отдаёт историю
   до момента добавления, поэтому:
   - контекст берём из `client_tg_messages` и `deal_messages` — они у нас
     уже есть и покрывают период с 13.04;
   - новые сообщения пойдут через care-бота сразу после добавления.
2. **Привязки можно проставить скриптом** для 25 клиентов из имеющихся
   данных. Это `scripts/care/link-chats.ts` — подготовлен, не запущен.
3. **Пилот собирается из 15 активных клиентов** с найденной группой. Это
   попадает в ступень «10–20», заложенную в плане, и выбор идёт по
   представительности, а не по техпризнаку: все пятнадцать — живые дела с
   перепиской за последние 90 дней.
4. **Клиенты 94 и 134**, на которых я предлагал опереться раньше, — плохой
   выбор: 94 в статусе `archived`, 134 — `completed`. Они попали в список
   только потому, что у них случайно заполнена привязка.

## Что чинить в действующей CRM

Это не работа контура v2, но без этого пилот упрётся:

1. **Автопривязка групп не работает** — ищет телефон в названии, которого
   там не бывает. Либо менять правило на сопоставление по ФИО с ручным
   подтверждением, либо добавлять телефон в название при создании группы.
   Пока не починено, каждая новая группа снова окажется непривязанной.
2. **У трёх активных кураторов нет учётной записи** (Чен, Евгения, Алина).
   Алина при этом ведёт 17 клиентов — больше всех. Сотрудника контура без
   `users.id` завести не к чему.
3. **У 6 клиентов в карточке только имя** без фамилии — их нельзя
   сопоставить ни с группой, ни с чем-либо ещё.
