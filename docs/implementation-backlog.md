# Backlog реализации E1–E6

_17 сентября 2026. Выход этапа E0 по `PRD-content-engine-mvp`, раздел 4._

## Как читаются оценки

Единица — рабочий день одного исполнителя. Оценки даны после аудита, а не до него,
и опираются на проверенное состояние кода (`docs/current-system-audit.md`).

Где оценка выросла относительно интуитивной, сказано почему. Где работа зависит от
действия Павла, задача помечена **[П]** и её срок не считается.

**Итого по этапам:**

| Этап | Дней | Комментарий |
|---|---|---|
| E1 Надёжность исполнения | 12–16 | включая сервер, Docker, учёт расходов, runbook |
| E2 Факты и калибровка | 14–18 | слой доказательств создаётся с нуля, не дорабатывается |
| E3 Ревизия архива | 5–7 | 80 страниц, из них критичных меньшинство |
| E4 Пакеты, outbox, редактор | 14–18 | самая большая схема и 10 экранов |
| E5 Атрибуция, Telegram, VK | 10–13 | из них 2–3 дня spike до любого кода |
| E6 Свежесть и исправления | 5–7 | переиспользует `safe-fetch.ts` |
| **Всего** | **60–79** | ≈ 12–16 недель при одном исполнителе |
