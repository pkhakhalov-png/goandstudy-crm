## 1.2 Как это проверить самому

**Важно: не проверяй со своего компьютера.** Твой исходящий IP — `92.241.87.90`,
он в nginx-allowlist. Сервер пропустит тебя как доверенного, и результат будет
выглядеть иначе, чем видит внешний мир. Я на этом чуть не сделал неверный вывод.

Честная проверка — с самого сервера, его IP в allowlist не входит:

```bash
ssh root@72.56.242.202
curl -s "https://goandstudy.com/wp-json/goandstudy-seo/v1/lookup?key=test"
```
Ожидается: `{"code":"gs_auth","message":"Нет подписи","data":{"status":401}}`

Расшифровка:
- `gs_auth` → мост живой, запрос дошёл до HMAC-проверки
- `rest_not_logged_in` → исключение в `gs-security.php` не сработало
- `404` → mu-plugin не подхватился
- окно basic-auth → правка nginx не применилась

Контроль, что остальное закрыто (оттуда же, с сервера):
```bash
for u in "wp-json/wp/v2/posts" "wp-json/" "wp-login.php"; do
  echo "$u → $(curl -s -o /dev/null -w '%{http_code}' https://goandstudy.com/$u)"
done
```
Ожидается 401 на всех трёх.


Практический вывод: basic-auth на `/wp-json/` был **не рутинной защитой,
а реагированием на инцидент**. Поэтому я открыл не весь REST, а только
namespace моста, защищённый HMAC.

## 2.2 Блокер, которого не было в задании

`gs-security.php` рубит REST для неавторизованных через фильтр
`rest_authentication_errors`. Он срабатывает **раньше**, чем `permission_callback`
моста, поэтому HMAC-проверка не успевала выполниться.

Без исправления мост возвращал бы `rest_not_logged_in` даже при открытом nginx.
Исправлено: в начало фильтра добавлено исключение для префикса
`/wp-json/goandstudy-seo/`. Остальной REST защиту не потерял.

## 2.3 У сайта нет технической SEO-базы

**Нет ни schema.org, ни SEO-плагина.** Ни Yoast, ни Rank Math, ни AIOSEO,
ни SEOPress. Meta пишет сама тема.

> **Поправка от 09.09, вечер.** Формулировка «нет canonical» была неверной —
> она сделана по главной странице. На внутренних страницах canonical есть, его
> печатает ядро WordPress (`rel_canonical`, только на singular). По данным нашего
> же обхода: из 159 страниц без canonical ровно одна — главная. Реальная дырка —
> **JSON-LD: его нет на 83 страницах из 159.** Приоритет — разметка, не canonical.
> Проверить: `curl -sL https://goandstudy.com/stipendii/ | grep -c 'rel="canonical"'`

159 страниц в sitemap, из них 77 — статьи блога.

Мост проставляет canonical/schema/description — **но только для постов,
которые создал сам** (условие: наличие меты `_gs_seo_key`). Существующие
159 страниц остаются без них.

Проверить: открыть исходник любой страницы, поискать `rel="canonical"`
и `application/ld+json`.
