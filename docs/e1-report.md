## 3. Тесты и результат

### Четыре обязательных теста PRD E1

| Требование | Как проверено | Результат |
|---|---|---|
| Смерть воркера: задача возвращается, не дублируется, старый результат не пишется | `seo-lease-test.ts` | ✓ запись отклонена по номеру выдачи |
| Задача длиннее 10 минут с heartbeat не перезапускается | `seo-lease-test.ts` | ✓ не тронута |
| Vercel не захватывает SSH-задачу | Маршрутизация `runner`, проверено в тестах | ✓ |
| Параллельные резервы не превышают лимит | `seo-budget-race.ts` | ✓ 20 попыток при запасе 10 → выдано ровно 10 |

### Сверх требования

- `seo-claim-race.ts` — двойная выдача: **0 дублей из 25** (до починки 5 из 12)
- Пачка задач не теряет сердцебиение, пока разбирается по очереди
- Месячный запас исчерпывается раньше суточного, когда узкий именно он
- Резерв под неизвестный исход не освобождается
- Лимит дорожки: пять задач при лимите два → выдано два
- `seo-selftest.ts` — 14 из 14, прогонялся после каждой правки

### Найдено по ходу, чего в аудите не было

| Что | Как проявлялось |
|---|---|
| Двойная выдача задачи | 5 дублей из 12 прогонов; шаг мог выполниться дважды |
| Таймаут на `gsc_daily` | Сборка контекста читала 198 тысяч строк; задача умирала после пяти попыток |
| Вечный трезвон сторожа | Старые падения уходили в чат каждые шесть часов бесконечно |
| Сердцебиение только за текущую задачу | После включения аренды дало бы двойное выполнение остальных четырёх из пачки |
| Возврат медленнее прежнего | Первая версия правила держала бы убитую функцию 17 минут вместо 10 |

## 5. Ограничения и компромиссы

**Проверить SQL прогоном не удалось.** `psql` на машине нет, Docker установлен,
но демон не запущен. Вместо исполнения — построчная вычитка и транзакция на
файл: миграция применяется целиком или не применяется вовсе.

**Учёт неполон.** Пять вызовов из восьми. Неполный учёт занижает расходы, и это
записано как задача, а не замолчано.

**Окно выпуска — предположение.** Данных по часам нет: Search Console даёт дни.
Вечер выбран по здравому смыслу и помечен в коде предположением. Проверяется по
`attribution_events`, когда наберётся месяц.

**Аренда 900 секунд подобрана, а не измерена.** Замеры шагов есть (бриф 122 с,
черновик 189 с, проверки 209 с), запас взят с большим избытком. Уточнять после
того, как появятся длинные шаги E2.

**`enqueue_nightly` не удалена.** Её могли переопределить руками; удалять то,
чего не могу прочитать, не стал.

## 6. Процедура отката

| Что откатить | Как |
|---|---|
| Правило возврата задач | `update seo.settings set value = to_jsonb(false) where key='lease_recovery';` |
| Выбор статьи для выпуска | `autopublish_order = 'legacy'` |
| Лимиты новых дорожек | Убрать ключи из `worker_concurrency_by_lane`; отсутствие ключа означает «без лимита» |
| Функции очереди | `*.rollback.sql` рядом с миграциями |
| Колонки | Не удаляются: в них данные текущих выдач, и PRD §14 требует отката без удаления |

Подробно — `docs/seo/runbook.md`, раздел 16.
